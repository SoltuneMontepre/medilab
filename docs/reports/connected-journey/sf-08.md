# SF-08 Laboratory setup: connected journey plan

## Position

Step 1 of the story; every later flow works on what it leaves. It runs on the demo database, not on an empty
laboratory, and walks only the parts of the SF-08 main path the story needs: the administrator creates one test
parameter `Journey nitrate {TAG}`, gives it an in-house way of testing, explicit applicability to one sample type
(unit, LOD, LOQ, decimals, default), a standard turnaround and a price with tax. The administrator then checks the
sampling requirement and the machine links of the method by opening them. These belong to the testing method, not to
the parameter, and the demo method already has them. An optional step adds a regulation limit. The Lab Head
authorizes the demo tester (US-LH04). Alternative paths SF-08-A1 to A5 are not walked: the journey needs no package,
role change, VAT change, approval chain change or template edit.

## Connection findings

1. **Sampling requirements and machine links are per method, not per parameter.** A new parameter on a demo method
   inherits them, and a second requirement for the same method and sample type is refused
   (`sampling_requirement.py:50`). The story's "administrator gives it sampling requirements and a machine link" can
   only be a check on screen (steps 2-3). Creating a link would mean linking another machine to TCVN 7602:2007, which
   changes Lead's planning as well. Nearest path: verify, do not create.
2. **Chemically wrong method choice.** No demo nitrate method exists. TCVN 7602:2007 (lead by AAS) is the only method
   with two usable machines (AAS-01, AAS-02; AAS-03 is under repair, `sol_demo/data/sol_laboratory/machine.xml:52`), so
   SF-05 can move the booking. LAB-CR6-01 (UV-Vis, one machine) would leave SF-05's booking without a slot. The
   alternative is to create a new method with steps, a sampling requirement and two machine links, about 25 more clicks.
3. **Shared machines with the WF-05 item.** Lead (Pb) on Bottled water defaults to the same TCVN 7602:2007 in-house way
   (`parameter_method_sample_type.xml:34-43`), so before WF-05 outsources it, both tests compete for AAS-01/AAS-02
   (capacity 1). Each machine also has 3-4 demo bookings. The plan still finds slots; WF-03/SF-10 must pick the booking by
   the journey parameter, not by machine.
4. **Doc/code mismatch on offered ways.** admin.md:60 says an in-house way is offered only when at least one person is
   authorized for its parameter. `parameter_method.py:195-197` says "Who may test a parameter is not checked yet", so
   the parameter is in the catalog right after step 11, before the Lab Head acts. The journey is unaffected because
   step 16 runs before WF-01. The rule itself is not built.
5. **Regulation limit is needed for a Pass/Fail.** If WF-01 orders the sample with QCVN 6-1 comparison, a result
   without a limit only accepts "Insufficient Basis" (`test_result.py:409-416`), and sending without a conclusion is
   refused (`test_result.py:436`). Step 13 avoids this; otherwise WF-04 must pick Insufficient Basis.
6. **Report language.** `name` is translatable. The administrator types it in English, and a Vietnamese report shows the
   English text unless a vi value is entered with the field's language button. This is harmless for the journey.
7. **Cypress uses direct URLs** (`/odoo/test-parameters`, `/odoo/parameter-authorizations`) and RPC for the checks
   (`laboratory-setup.cy.js:120-138`). No step of this flow needs RPC; every value can be checked on the list rows.
8. Business-flows "Starts from: an empty laboratory" does not match the journey, which starts from the demo data. No
   cron, external service or e-mail is involved in this flow.
