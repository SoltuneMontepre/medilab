# WF-03 Testing assignment and scheduling: connected journey plan

## Position

Step 8 of the story, after WF-02 (the head of Chemistry scanned the label) and SF-11 (folders, no effect on scheduling), before SF-10, SF-05 and WF-04. The journey walks the WF-03 main path for the task of `Journey nitrate {TAG}` only: the head assigns one task to the authorized tester from the department queue, the department plan proposes a booking of the accepted way, the head approves it, and the tester sees it. WF-03-A2 is walked implicitly (the booking reserves tester and machine, plus rooms when the method has a bookable step). WF-03-A1, A3, E1 and E2 are not walked. The second test of the sample (Lead (Pb)) stays unassigned in the Chemistry queue for WF-05.

The code implements the TARGET scheduler of `docs/reports/wf-03-test-plan.md`, not its "AS-IS": bookings are `proposed → scheduled → in_progress → done` (`models/testing/machine_booking.py:124-136`), with a department plan (`machine_booking_plan.py:31-72`), parameter authorization (`machine_booking_eligibility.py`), OverTime (`overtime.py`), pinning (`machine_booking.py:139`) and at-risk flags. There is no `queued` state in the code. Paths below are relative to `src/core/modules/sol_laboratory/` unless stated.

## Data

- `{SAMPLE}`: the sample code WF-02 read from the label. Searches use it or `Journey nitrate {TAG}`; never the task's Lead name.
- Assignee picked: `Dang Thi Lan` (`sol_demo.demo_person_tester`, user `demo.tester`).
- `{MACHINE}`: `AAS-01 Atomic absorption spectrometer 1` (`sol_demo.demo_machine_aas`, link `sol_demo.demo_machine_method_aas_lead`, 30 min) when step 0 freed it, else `AAS-02 Atomic absorption spectrometer 2` (`sol_demo.demo_machine_aas_2`, link `sol_demo.demo_machine_method_aas_2_lead`, 40 min). The spec reads it from the Recommendation group and the Bookings row; it does not hard-code it.
- `{BOOKING_START}`: the earliest quarter hour after now in Dang Thi Lan's working time (company calendar, Asia/Ho_Chi_Minh) where the machine is free, before the due date. During working hours it can be 15 to 30 minutes away; outside them, the next working day 08:00, or an evening of a still-future demo OverTime record (`sol_demo/data/sol_laboratory/overtime.xml`). Always in the future at approval.
- Demo records relied on: `sol_demo.demo_hr_department_chemistry`, `sol_demo.demo_person_head_of_department`, `sol_demo.demo_person_tester`, `sol_demo.demo_testing_method_tcvn_7602`, `sol_demo.demo_machine_aas`, `sol_demo.demo_machine_aas_2`, their calibrations `sol_demo.demo_machine_service_aas_calibration` / `_aas_2_calibration`, `sol_demo.demo_machine_booking_lead_running` (step 0), `sol_demo.demo_test_parameter_lead` (second test).

What SF-08 must have configured for a booking to be proposed and approvable (the SF-08 → WF-03 connection; `machine_booking.py:581-640`, `machine_booking_conditions.py:100-160`, `sample_test_eligibility.py`):

1. Way of testing (`medilab.parameter.method`, parameter form tab Ways of Testing, `method_ids`): `parameter_id` = the new parameter, `method_id` = TCVN 7602:2007, `department_id` = Chemistry (the department of the head and of the tester; the task queue follows it), no `subcontractor_id`. It must be the only in-house way, because WF-01 accepts one way and the plan books only the accepted way (`machine_booking.py:603-604`).
2. Applicability (`applicability_ids`): that way on the sample type WF-01 orders (Bottled water); the plan searches ways by `applicability_ids.sample_type_id` (`machine_booking.py:598-601`).
3. Machine-and-method link (`medilab.machine.method`, machine form tab Testing Methods): at least one link of the way's method to a machine with `duration_minutes` > 0 and `capacity` ≥ 1, the machine In Use, active, with a calibration whose next due date is after the booking's end, no overdue maintenance, no downtime over the slot, and not held by an in-progress booking past its end. Without any link the way's own `duration_minutes` must be set (no-machine way).
4. Rooms/locations: none needed. A method step in a bookable location would also need that location free for the step's time; TCVN 7602 has none.
5. Turnaround (`turnaround_days`, 3): gives WF-01's expected date, from which the due date is one working day earlier (`sample_test_due_date.py:65-75`, default safety margin 1). The due date must leave at least one working-time slot of the tester after reception.
6. Authorization (`medilab.parameter.authorization`): Dang Thi Lan → the parameter. Without it she is not offered in step 4, the plan books nobody (`machine_booking_plan.py:96-97`) and Approve Booking is refused.
7. Tester and head in the way's department (both Chemistry in `sol_demo/data/sol_laboratory/person.xml:28-45`).

## Connection findings

1. **AAS-01 never takes a booking on a demo database older than a few hours.** The demo booking `demo_machine_booking_lead_running` is In progress on AAS-01 with an end at 09:30 (Vietnam) of the install day (`sol_demo/data/sol_laboratory/machine_booking.xml:13-20`); an in-progress booking past its end holds its machine (`models/testing/machine_booking_conditions.py:144-155`, by design in `docs/specs/scheduling.md` "Releasing the machine"). So the plan proposes only AAS-02 (AAS-03 is under repair), and SF-05 putting AAS-02 under repair leaves no machine: the booking stays proposed without a slot, outsourcing is suggested, and it comes back only when AAS-02 returns to use. The same holds ICP-MS-01 (`demo_machine_booking_lead_overrun`, lines 149-156). Click-only fix: step 0, the head (or Ly Van Hung) marks that demo booking Done on the Machine Schedule. SF-05 then repairs `{MACHINE}` and the plan moves the booking to the other AAS.
2. **"Assign Sample", the Cypress main path, would also assign the Lead task.** `action_assign_sample` collects every unfinished testing task of the sample in the department (`models/tasks/task.py:446-459`), the dialog's `task_ids` is read-only (`views/tasks/task_reassign_views.xml:9`), and Dang Thi Lan is authorized for Lead too, so both tasks would go to her and Lead would get a booking for her. The single-task path is list selection → Actions → Assign (steps 2-3). The task form's own Assign button cannot be reached by a click from any task list, whose rows open the sample test (`task_views.xml:7`); Cypress reaches it with `cy.openRecord` (direct URL, `testing-scheduling.cy.js:62-70`).
3. **The second (Lead) task.** It stays Open in the Chemistry queue; the tester sees it in Awaiting Tasks with a Claim button (she must not claim it). The plan gives its test a proposed booking without a person (`machine_booking_plan.py:74-115`), which holds a machine only inside the plan calculation; it can push the nitrate proposal to a later slot or share AAS-02's interval (same method, same sample, `machine_booking.py:704-731`) but blocks no approval. When no machine can finish it in time (likely: AAS-01 and ICP-MS-01 held, see 1), `outsourcing_suggested` is set and it shows in Schedule → Outsourcing Suggestions. WF-05's Outsource button needs a subcontracted way with the accepted method (`sample_test.py:508-528`): Northern testing offers Lead by ISO 17294-2:2016 only, so WF-01 must accept Lead by the ICP-MS way (ISO 17294-2:2016), not by AAS TCVN 7602, or WF-05 is refused ("needs a revised quotation"). Leaving the task alone blocks nothing in WF-03; the sample cannot complete until WF-05 finishes it.
4. **SF-07 dates can remove the slot.** The due date is the end of the day one working day before the expected date (`sample_test_due_date.py:65-75`). If SF-07 accepts a requested date of today or tomorrow, the due date is today or already passed, `_recommend` returns nothing (`machine_booking.py:595-597`), the test is flagged for outsourcing and Approve Booking never appears. SF-07's requested date must be at least 3 working days ahead.
5. **The department scan is required.** Without the Chemistry handover's `received_at`, no recommendation is computed and approval is refused ("waits until its department receives its sample", `models/testing/sample_test_eligibility.py:24-40`). Cypress stands in for it with `receive_by_label` over RPC (`flows/wf-03-testing-scheduling/setup.js:87-99`); the journey relies on WF-02's scan.
6. **The approved slot can differ from the one the head read.** If a quarter-hour boundary passes between step 7 and step 8, the proposal is stale and `action_approve_booking` recalculates the plan and approves the new slot without a message (`models/testing/sample_test.py:436-449`). Cypress waits it out (`setup.js:61-68`). The spec must take `{BOOKING_START}`/`{BOOKING_END}` from the Bookings row after approval.
7. **Reminders need a cron.** The F-25 reminder 15 minutes before the start is sent by `sol_laboratory.ir_cron_notifications_remind` (Cypress triggers it over RPC, `setup.js:318-322`). No business screen runs it; only Settings → Technical → Scheduled Actions → Run Manually in developer mode as the administrator. The journey does not check reminders.
8. **Notification channel.** Assignment and approval notifications go to the inbox only when the tester's channel preference for those events includes the popup channel; otherwise they are e-mailed (`models/notifications/mail_message.py:106-120`). Step 10 is a check only if the inbox channel is on.
9. **Task names are written in the staff language.** Testing task names are `"{code}: {parameter display name}"` (`sample_test.py:399`), and staff text is written in Vietnamese when it is installed (`services/staff_language.py`). The Lead task may read `… Chì (Pb)`; search by `{SAMPLE}` or the journey parameter name, which has no translation.
10. **Test plan document outdated.** `docs/reports/wf-03-test-plan.md:19-21` says the code is a `queued` machine queue without authorization, pinning, OverTime or at-risk flags, and that epic #405 is not built; the code has all of them. The document should be updated by its owner.
11. **The test stays Assigned after approval.** Business flows list "assigned → testing" for WF-03; the move to Testing happens only when the booking starts (`sample_test.py:601-603`), which is WF-04's first click.
