# WF-05 Outsourced testing: connected journey plan

## Position

Story step 12. It follows WF-04, which leaves the in-house test `Journey nitrate {TAG}` approved and the sample's
second test, **Lead (Pb)**, untouched in the Chemistry queue. It precedes SF-01 and WF-06: approving the lead result
completes the sample and the test request, which drafts the report. The journey walks WF-05-A3 (the head outsources
the waiting lead test straight away with a reason) and then the main path: the test joins Northern's draft dispatch,
the head names the sample delivery staff, they hand it over (dispatch sent), the subcontractor confirms receipt and
enters the result on the portal, a Chemistry tester sends it for approval and the head approves. WF-05-A1, A2 and
E1 to E4 are not walked. If the lead test already carries a scheduler suggestion when the head opens it, the dialog
has no reason field and the same clicks walk the main path's "accept the suggestion" instead (finding 4).

**Pick for the second test (align WF-01, WF-02, SF-06, SF-08):** parameter **Lead (Pb)**
(`sol_demo.demo_test_parameter_lead`), sample type **Bottled water** (`sol_demo.demo_sample_type_bottled_water`),
method chosen by the customer in the cart **ISO 17294-2:2016** (option "Lead (Pb) – ISO 17294-2:2016", which
becomes the accepted in-house Chemistry way `sol_demo.demo_parameter_method_lead_icpms`), subcontractor **Northern
Testing Laboratory** (`sol_demo.demo_subcontractor_northern_testing`, VILAS 101, subcontracted way
`sol_demo.demo_parameter_method_lead_subcontracted`), portal login **`demo.subcontractor` / `demo`** (contact Nguyen
Thi Lan). Demo data leaves Northern's accreditation valid until install date + 2 years
(`sol_demo/data/sol_laboratory/subcontractor.xml:3-9`), so outsourcing works without SF-06's renewal; SF-06 must only
keep the expiry in the future.

The trigger, exactly: the head's **Approve** on the lead result sets the result `approved` →
`sample_test._progress("approved")` → `sample._follow_tests()` turns the sample `completed` (all non-cancelled tests
approved, `sample.py:72-83, 329-344`) → the request moves `testing` (or `awaiting_approval`) → `completed` → draft
report + Lab Head signing task. WF-04's nitrate approval must already be done; whichever approval comes last
triggers it.

## Connection findings

1. **The subcontractor's result does not go to the head; a tester must send it.** business-flows.md WF-05 and
   `subcontractor.md` ("Approval": goes to the head as soon as entered, the head is notified) disagree with the code:
   `_portal_enter_result` creates the result unsigned and "waits for the laboratory to send it for approval"
   (`subcontract_dispatch.py:251-276`); the result chain has a Tester level (same department) before the Head level
   (`approval_level.xml:16-31`), and the head cannot sign both levels (`approval_mixin.py:280`,
   `test_result.py:515-526`). No task or notification tells a tester the result is waiting; the head is notified at
   receipt (`subcontract_dispatch_delivery.py:108-122`) and when the tester sends (`test_result_notification.py`).
   Cypress also has the tester sign (`outsourced-testing.cy.js`, "The tester sends the subcontractor's result").
   Journey: steps 15-16 add `demo.tester`, who finds the result by menu search.
2. **WF-01 must accept the ICP-MS method, not the AAS default.** On bottled water the default lead way is AAS
   (`parameter_method_sample_type.xml:34-42`), and no subcontractor tests lead by AAS. With AAS accepted, the Outsource
   button is hidden and a hint shows (`sample_test_views.xml:23,137-143`) and outsourcing is refused
   (`sample_test.py:508-520`). The customer must select "Lead (Pb) – ISO 17294-2:2016" in the cart's
   `select[name=parameter_method_id]` (one option per method, in-house preferred: `test_parameter.py:171-186`), which
   stores `accepted_method_id` = `lead_icpms` (`test_request.py:194-207`) and puts the task in Chemistry
   (`sample.py:628-645`).
3. **The journey's test joins a dispatch it does not own.** `_send_to_subcontractor` puts the test in Northern's oldest
   draft dispatch (`sample_test.py:543-547`). sol_demo leaves one, `demo_subcontract_dispatch_draft`, with four demo
   lead tests (`sol_demo/demo_dispatches.py:69-72, 96-97, 125`); an earlier Cypress `clearDrafts` cancels it, and an
   earlier journey run sends it. Consequence: the hand-over in step 8 also sends those demo tests, and the portal page
   shows several rows. Workable: read `{DISPATCH}` from the form, locate the row by `{LAB}`, and do not count rows.
   Cancelling the demo draft first would leave its tests outsourced with no dispatch and change Cypress's starting
   data, so the journey does not.
4. **A real outsourcing suggestion cannot be produced on demand.** `outsourcing_suggested` is set only when the
   department plan finds no ICP-MS slot before the test's due date (`machine_booking_plan.py:45-62`,
   `machine_booking.py:561-578, 581-635`; only the accepted way counts). ICP-MS-01 has free 4-hour slots with
   capacity 20 (`machine_method.xml:8-14`), so with a normal due date no suggestion appears. To get one by clicks:
   SF-05 puts ICP-MS-01 under repair while the lead test waits (`_requeue` recalculates every plan,
   `machine_booking.py:545-558`), or SF-07 gives a requested date already too close for ICP-MS. In the story, SF-05
   runs before WF-04 and returns the machine to use, which clears the flag again, and SF-07's feasibility check
   keeps dates feasible. So the journey uses WF-05-A3, and branches to the accept path if the alert of step 2 is
   shown.
5. **Expected date: demo data and Cypress disagree.** Northern's lead way has `turnaround_days` 3
   (`parameter_method.xml:15-20`); the seed sets 6 only when it is empty (`sol_demo/demo_dispatch_delivery.py:20-23`),
   but `outsourced-testing.cy.js` asserts today + 6. The journey asserts Results Expected = Date Sent + the turnaround
   shown on Northern's way, not a fixed number.
6. **Notifications are not a click path.** Receipt raises `EVENT_DISPATCH_RECEIVED` through `mail.message.raise_event`
   (`notifications/mail_message.py:71-101`), and sample delivery staff get no to-do for a dispatch to carry, only the
   menu list. The journey uses menus and checks the receipt notification only as optional step 14.
7. **The lead test must not be started or reassigned elsewhere upstream.** Outsourcing straight away needs status
   `waiting`/`assigned` and the head's department equal to the testing task's (`sample_test.py:468-485`). WF-03,
   SF-10 and WF-04 must touch only the nitrate test. A scheduled lead booking is harmless (cancelled on outsourcing,
   `sample_test.py:589-594`); a started one blocks WF-05.
8. **Comparison with a regulation adds a field.** If WF-01 asked for comparison (e.g. QCVN 6-1), the tester must set a
   conclusion before sending (`test_result.py:436-441`). Simplest: WF-01 requests no comparison.
9. **Draft report preparation depends on a cron.** `_open_signing_task` wakes the PDF-preparation scheduled job
   (`test_report.py:241-248`); a user cannot run it. The signing task and draft report exist at once; the PDF is
   WF-06's concern.
10. **Cypress shortcuts this plan replaces.** `setup.js` creates and receives the request and assigns the task over RPC
    (`assignedTest`), outsources through the wizard model (`outsourcedTest`), sets courier and sends over RPC
    (`sentDispatch`), confirms receipt with `portalPostAs` (`receivedDispatch`), and E1 visits `/my/dispatches/<id>`
    directly. Every one has a click path above.
