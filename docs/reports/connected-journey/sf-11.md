# SF-11 Laboratory file administration: connected journey plan

## Position

Story step 7, between WF-02 (the head of department scanned the journey's sample, its tests wait in the department queue) and WF-03 (the head assigns the journey parameter's task). The journey walks the back-office part of the SF-11 main path (the head creates the raw-data and result folders of the journey's sample), adds the tester through the administrator's Members tab (the clickable form of SF-11-A1, see finding 1), lets the tester browse the empty folders in the back office (WF-04-A10, browse only), and walks SF-11-A4 (turn off, turn on). SF-11-A3 (archive) is planned as a step for the very end of the journey, not at step 7. SF-11-A2, SF-11-E1 and SF-11-E2 are not walked (findings 3, 5, 6); the WF-04 file paths main-path file part, A6-A9 and E4-E6 cannot be reached by browser clicks (finding 2).

## Connection findings

1. **The head (folder owner) cannot add a member in the back office; only Medilab Sync (the API) or an administrator can.** Holders of the laboratory files permission get only read access to folders and members (`security/laboratory_files_access.xml:7-20`); a permission's group grants only its own operation (`models/system/permission.py:292-300`), so `create_all` on folders gives no write on the folder and no create on members (`permission_laboratory_folder_member_create_all` is not in the head's roles, `sol_demo/data/sol_laboratory/role.xml:145-203`). The spec says so: "owners manage their folders from Medilab Sync" (`docs/specs/laboratory-files.md:66`), and Cypress adds members only through the API (`flows/wf-07-laboratory-files/setup.js:85-90`, `laboratory-files.cy.js:126`). Consequence: the SF-11 main path "the head adds testers as members" is not clickable. Nearest paths: (a) the administrator adds the tester on the folder's Members tab (steps 8-9, used in this plan); (b) skip the member step and let WF-03's assignment add the tester automatically (`sample_laboratory_folders.py:113-140`), moving steps 11-14 to after WF-03.
2. **No file can be uploaded to a sample folder from the browser.** Files, versions, locks and devices have `create="0" edit="0"` lists and forms (`views/laboratory_files/laboratory_file_views.xml:9,24`, `laboratory_file_version_views.xml:8,27`); there is no upload button or binary field; versions are stored only by `_add_version()` through the API upload flow (prepare, presigned PUT to the bucket, finalize, verification job) or an online-editor save, which needs an existing Office file with a version (`laboratory-files.md:258-261`). Consequence: a browser-only journey reaches SF-11 main path (folder creation), SF-11-A1 (administrator variant), SF-11-A3, SF-11-A4, and WF-04-A10 only as "browse empty folders". It cannot reach the WF-04 main-path file part (save file, Medilab Sync upload, head signs the result-file version), WF-04-A6, A7, A8, A9, E4, E5, E6, SF-11-A2 or the "turned-off folder refuses uploads" check. Result-file signing is therefore out of the click journey; WF-04's result entry (test result form) is unaffected. The only click-reachable file signing is on demo file `Pb-ket-qua.xlsx` of `sol_demo.demo_sample_bottled_water_testing` (`sample_folders.cy.js:36-49`), which is not the journey's sample.
3. **Medilab Sync binding is a desktop app.** The browser part ends at the testing task's "Download Medilab Sync" / "Open in Medilab Sync" buttons, which redirect to GitHub releases and a `medilab-sync://connect` link (`flows/wf-07-laboratory-files/sync-setup.cy.js:28-42`); the journey may check the buttons are shown on the WF-03 task, nothing more.
4. **Running order of A3.** Archiving is final ("There is no unarchiving", `laboratory-files.md:55`), makes the folder, members and rules read-only and stops WF-03's assignment from adding members to it (`sample_laboratory_folders.py:131-135`); the sample also never offers Create Folders again because it still has a folder of that category (`_compute_laboratory_folders_missing`). Nothing downstream in the journey reads sample folders (reports use the shipped Report Drafts folder, `models/testing/test_report_preparation.py:229`), so archiving the raw-data folder after step 18 is safe; archiving at step 7 would contradict the story.
5. **SF-11-E1 (release an abandoned lock) is not reachable.** Locks are taken only through the API (`laboratory_file_locks.cy.js:7-15` uses a server action for this). The only active demo lock, on `HPLC/duong-chuan-Pb.csv` (`sol_demo.demo_laboratory_file_lock_calibration`), is seeded with a 30-minute life (`sol_demo/demo_laboratory_file_locks.py:17-21,59`), and the cron `laboratory_file_locks.expire` marks it expired every 5 minutes; "Release" on a lock past its expiry records it as expired, not released (`models/laboratory_files/laboratory_file_lock.py:121-130`). The File Locks list (`menu_laboratory_file_lock`, default filter Active) will normally be empty.
6. **SF-11-E2 (revoke a device) is clickable but not repeatable.** Demo devices: PC-HPLC-01 (tester), PC-AAS-01 (chemistry tester), LAPTOP-HUNG (already revoked), and phones (`sol_demo/demo_laboratory_files.py:17-58`, `data/sol_laboratory/laboratory_device.xml`). Laboratory → Documents → Devices (`menu_laboratory_device`) row button `button[name=action_revoke]` with a confirm dialog works by click, but revoking is final (`laboratory-files.md:451`): a second journey run finds the row Revoked, and PC-HPLC-01 is used by `laboratory_folders.cy.js:30-31` and the lock spec. Devices made for the journey would need the sign-in API. Not walked; at most check that LAPTOP-HUNG shows Revoked without a Revoke button.
7. **Folder names depend on the head's language.** The category word is `_description_selection(self.env)` of the creating user (`sample_laboratory_folders.py:89,108`); with the head on vi_VN the names would not read "Raw Data"/"Results". Search by `{LAB_CODE}` only, and assert the two rows by count and category column, not by the English words.
8. **Business-flows mismatch.** SF-11 main path puts member addition on the head; the code and spec put it on Medilab Sync, and both WF-03 (`_follow_assignment`) and the head-of-department feature ("adds testers by hand only for anything else", `head-of-department.md:147`) make automatic membership the normal route. SF-11 at story step 7 duplicates what WF-03 does on assignment.
9. **External services.** Steps 1-15 and L1-L3 need neither Garage nor ONLYOFFICE: creating folders, members, turning off/on and archiving touch only the database; the empty folders have no versions to download. Garage is needed only for a version download (`action_download`, presigned URL) and ONLYOFFICE only for opening an Office file from the Files list, neither of which the journey's sample can reach.
