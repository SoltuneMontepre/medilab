## Connection findings

1. **The head (folder owner) adds members only in Medilab Sync; the back office gives the owner no way.** Holders of the laboratory files permission get only read access to folders and members (`security/laboratory_files_access.xml:7-20`); a permission's group grants only its own operation (`models/system/permission.py:292-300`), so `create_all` on folders gives no write on the folder and no create on members (`permission_laboratory_folder_member_create_all` is not in the head's roles, `sol_demo/data/sol_laboratory/role.xml:145-203`). This matches the documents: "owners manage their folders from Medilab Sync" (`docs/specs/laboratory-files.md:66`), with Manage access in Medilab Sync (`medilab-sync.md:39`); Cypress adds members only through the API (`flows/wf-07-laboratory-files/setup.js:85-90`, `laboratory-files.cy.js:126`). On the live app the head's folder form is read-only, its Members tab has no "Add a line", the Folder Members list has no New button. The journey writes the step as outside the browser, so the tester is not a member after SF-11; WF-03's assignment adds her (`sample_laboratory_folders.py:113-140`). Only an administrator adds a member in the back office, which the main path does not give him.
2. **No file can be uploaded to a sample folder from the browser.** Files, versions, locks and devices have `create="0" edit="0"` lists and forms (`views/laboratory_files/laboratory_file_views.xml:9,24`, `laboratory_file_version_views.xml:8,27`); there is no upload button or binary field; versions are stored only by `_add_version()` through the API upload flow (prepare, presigned PUT to the bucket, finalize, verification job) or an online-editor save, which needs an existing Office file with a version (`laboratory-files.md:258-261`). Confirmed on the live app for the tester and the head: neither the folder's Files tab nor the Files list offers a line, a New button or an upload field. WF-04 owns saving files; the documents put it in Medilab Sync. Consequence: a browser-only journey reaches SF-11's folder creation, SF-11-A1 (administrator variant), SF-11-A3, SF-11-A4, and WF-04-A10 only as "browse empty folders". It cannot reach the WF-04 main-path file part (save file, Medilab Sync upload, head signs the result-file version), WF-04-A6, A7, A8, A9, E4, E5, E6, SF-11-A2 or the "turned-off folder refuses uploads" check. Result-file signing is therefore out of the click journey; WF-04's result entry (test result form) is unaffected. The only click-reachable file signing is on demo file `Pb-ket-qua.xlsx` of `sol_demo.demo_sample_bottled_water_testing` (`sample_folders.cy.js:36-49`), which is not the journey's sample.
3. **Medilab Sync binding is a desktop app.** The browser part ends at the testing task's "Download Medilab Sync" / "Open in Medilab Sync" buttons, which redirect to GitHub releases and a `medilab-sync://connect` link (`flows/wf-07-laboratory-files/sync-setup.cy.js:28-42`); the journey may check the buttons are shown on the WF-03 task, nothing more.
4. **Running order of A3.** Archiving is final ("There is no unarchiving", `laboratory-files.md:55`), makes the folder, members and rules read-only and stops WF-03's assignment from adding members to it (`sample_laboratory_folders.py:131-135`); the sample also never offers Create Folders again because it still has a folder of that category (`_compute_laboratory_folders_missing`). Nothing downstream in the journey reads sample folders (reports use the shipped Report Drafts folder, `models/testing/test_report_preparation.py:229`), so archiving the raw-data folder after step 18 is safe; archiving at step 7 would contradict the story.
5. **SF-11-E1 (release an abandoned lock) is not reachable.** Locks are taken only through the API (`laboratory_file_locks.cy.js:7-15` uses a server action for this). The only active demo lock, on `HPLC/duong-chuan-Pb.csv` (`sol_demo.demo_laboratory_file_lock_calibration`), is seeded with a 30-minute life (`sol_demo/demo_laboratory_file_locks.py:17-21,59`), and the cron `laboratory_file_locks.expire` marks it expired every 5 minutes; "Release" on a lock past its expiry records it as expired, not released (`models/laboratory_files/laboratory_file_lock.py:121-130`). The cron "Expire laboratory file locks" is active and runs every 5 minutes, so the File Locks list (`menu_laboratory_file_lock`, default filter Active) will normally be empty.
6. **SF-11-E2 (revoke a device) is clickable but not repeatable.** Demo devices: PC-HPLC-01 (tester), PC-AAS-01 (chemistry tester), LAPTOP-HUNG (already revoked), and phones (`sol_demo/demo_laboratory_files.py:17-58`, `data/sol_laboratory/laboratory_device.xml`). Laboratory → Documents → Devices (`menu_laboratory_device`) row button `button[name=action_revoke]` with a confirm dialog works by click, but revoking is final (`laboratory-files.md:451`): a second journey run finds the row Revoked, and PC-HPLC-01 is used by `laboratory_folders.cy.js:30-31` and the lock spec. Devices made for the journey would need the sign-in API. Not walked; at most check that LAPTOP-HUNG shows Revoked without a Revoke button.
7. **Folder names depend on the head's language.** The category word is `_description_selection(self.env)` of the creating user (`sample_laboratory_folders.py:89,108`); with the head on vi_VN the names would not read "Raw Data"/"Results". The demo head, tester and administrator work in en_US, so the names are `{LAB_CODE} Raw Data` and `{LAB_CODE} Results`. The spec searches by `{LAB_CODE}`, finds the two rows by their category column and hands over the names as shown.
8. **Two routes to membership.** SF-11's main path has the head add testers as the folders' owner, in Medilab Sync; WF-03 (`_follow_assignment`) and the head-of-department feature ("adds testers by hand only for anything else", `head-of-department.md:147`) make the assignment add them. SF-11 at story step 7 creates the folders WF-03 would otherwise create on assignment.
9. **External services.** The steps and the archive need neither Garage nor ONLYOFFICE: creating folders, members, turning off/on and archiving touch only the database; the empty folders have no versions to download. Garage is needed only for a version download (`action_download`, presigned URL) and ONLYOFFICE only for opening an Office file from the Files list, neither of which the journey's sample can reach.
10. **Only members see a sample's folders.** Seen on an earlier run: before the tester is a member, her sample form shows no "Folders" stat button; once a member, the button counts 2. An administrator's Turn Off (SF-11-A4) keeps the folder listed for its members, with a red Turned Off badge, and its form still opens with its members and files; Turn On restores In Use. That a turned-off folder refuses uploads cannot be checked by clicks (finding 2).
