# SF-06 Accreditation and registration renewal: connected journey plan

## Position

Step 2 of the story, right after SF-08 and before any order exists. The administrator walks the SF-06 main path:
records the accreditation certificate the laboratory received, `VILAS {TAG}`, and imports its scope line, so that the
journey's in-house nitrate test is accredited. No alternative path is walked. SF-06-A2 (an expired subcontractor
cannot be chosen, renewing it makes it selectable) needs demo data past its expiry, which the fresh demo database does
not have for the subcontractor of the story, and the chain does not lapse demo data to see a refusal (finding 7).
SF-06-A1 (quality dossier) cannot be set up by clicks (finding 2). SF-06-A3 (archive or restore a certificate) is not
walked.

The spec is `src/tests/playwright/journey/02-sf-06-accreditation-renewal.spec.js`.

## Connection findings

1. **No accreditation mark is printed on the report.** business-flows.md says reports carry "the accredited and
   registered marks", but the report builder only prints quality-registration marks (`test_report.py`) and nothing
   reads `is_accredited` outside views. Consequence: WF-06 cannot check an "accredited" mark on the PDF. The
   click-visible proof of the main path is the Accredited checkbox on the parameter's applicability (step 3), on the
   nitrate sample test form and in the sample's Tests tab. Mismatch to raise with the owner.
2. **A way of testing cannot be found when adding it to a quality dossier (SF-06-A1).** On Quality Registrations →
   dossier → Covered Ways of Testing → Add a line, the dialog lists the ways by their ID alone and its search box offers
   only "Custom Filter…": ways of testing have no list or search view of their own. The administrator cannot tell which
   row is `Journey nitrate {TAG} – LAB-CR6-01`, so the journey does not register it and the WF-06 report prints no
   dossier mark for the nitrate row. Renewing the dossier's Valid Until alone is clickable but connects to nothing in
   the story: the demo dossier covers Lead (Pb) by TCVN 7602:2007, not the ISO 17294-2:2016 way the journey accepts.
3. **"Import" is a typed dialog, not a file.** The import is a list edited in the dialog (code, title, parameters,
   sample types); no CSV or XLSX upload exists.
4. **The typed code must equal the method's code exactly.** The dialog links an existing method only on an exact code
   match; any other spelling silently creates a new method, the line then does not cover the nitrate way and the test
   is not accredited (`accreditation_certificate_import.py`). The spec types the code SF-08 read from the screen and
   checks the imported row.
5. **A certificate per run instead of a line on VILAS 118.** The demo certificate stays as installed; each run leaves
   one certificate `VILAS {TAG}`. Its parameter can never be deleted later (parameters are restricted on scope lines).
6. **WF-01 must keep the same sample type and accept the right lead method.** The nitrate test is accredited only if
   the journey's sample is Bottled water (or a child of it). For WF-05 to outsource Lead (Pb) to Northern, the
   customer's accepted lead way must use ISO 17294-2:2016; the default lead way on Bottled water is TCVN 7602:2007.
7. **SF-06-A2 is not walked.** On a fresh demo database Northern Testing Laboratory, the subcontractor WF-05 sends
   the Lead (Pb) test to, is valid until today + 2 years; the only expired one, Coastal Analytical Services, has no
   subcontracted way and Cypress TC-F37-03 relies on it staying expired. Seeing the refusal would need the
   administrator to lapse a valid accreditation, which no business step does. When the journey walked it, the lapsed
   subcontractor was missing from the Subcontractor suggestions of a new way of testing (only `Create "…"` was
   offered) and renewing the date brought it back. WF-05 takes Northern Testing Laboratory as demo data; SF-06 no
   longer hands over `subcontractorName`.
8. **Head notification of draft dispatches (SF-06-A2) and the dossier expiry warning (SF-06-A1) are cron-only.** No
   journey dispatch exists at this step, so neither is walked.
9. **Accreditation is recomputed by a daily job as well**, but importing the line recomputes matching applicabilities
   and open tests at once, so no cron is needed in the journey.
