# SF-06 Accreditation and registration renewal: connected journey plan

## Position

Step 2 of the story, right after SF-08 and before any order exists. The administrator walks the SF-06 main path
(adds a scope line to the valid demo certificate so that the journey's in-house nitrate test will be accredited),
SF-06-A2 (renews the accreditation of Northern Testing Laboratory, the subcontractor WF-05 outsources the Lead (Pb) test
to, optionally first letting it lapse to show it cannot be chosen) and, optionally, SF-06-A1 (renews the valid quality
dossier and adds the journey's nitrate way to it, so the WF-06 report prints a dossier mark). SF-06-A3 (archive/restore a
certificate) is not walked: archiving VILAS 118 would un-accredit every demo test.

## Connection findings

1. **No accreditation mark is printed on the report.** business-flows.md:571 says reports carry "the accredited and
   registered marks", but the report builder only prints quality-registration marks (`_print_marks`,
   `models/testing/test_report.py:411-433`; `_print_row` 450-468) and nothing reads `is_accredited` outside views
   (grep of `sol_laboratory`, `sol_commerce`). admin.md:68,77 also specify accreditation only per sample test. Consequence:
   WF-06 cannot check an "accredited" mark on the PDF. The click-visible proof of the main path is the "Accredited"
   checkbox on the nitrate sample test form (`sample_test_views.xml:132`) and the sample's Tests tab
   (`sample_views.xml:175`), checked from WF-02 onward and frozen at WF-04 approval. Only a dossier mark (A1, `(*)`)
   reaches the report. Mismatch to raise with the owner.
2. **"Import" is a typed dialog, not a file.** The import wizard is an editable list (code, title, parameters, sample
   types) in a modal (`accreditation_certificate_import_views.xml`; Cypress TC-F412-01 types it the same way); no
   CSV/XLSX upload exists, so no fixture file is needed. A scope line can also be typed directly in the certificate's
   editable Scope list (`accreditation_certificate_views.xml:43-52`), which picks the method from a dropdown and avoids
   the trap below; use it as fallback.
3. **The typed code must equal `{METHOD}` exactly.** The wizard links an existing method only on an exact code match;
   any other spelling silently creates a new method (`accreditation_certificate_import.py:60-66`), the line then does
   not cover the nitrate way, and the test is not accredited. The plan therefore needs SF-08's method code verbatim.
4. **What SF-06 depends on from SF-08 besides the parameter and its way.** The way must be in-house (department, no
   subcontractor: subcontracted applicabilities/tests are never accredited, `parameter_method_sample_type.py:91-96`,
   `sample_test.py:197`); it must have a Sample Types row for Bottled water (or a descendant of what the line names),
   otherwise step 7 has nothing to show and WF-01 cannot offer it; and the parameter must be saved under the exact name
   so the `parameter_ids` dropdown finds it. Which machine SF-08 linked does not matter to accreditation.
5. **WF-01 must keep the same sample type and accept the right lead method.** The nitrate test is accredited only if
   the journey's sample is Bottled water (or a child of it). For WF-05 to outsource Lead (Pb) to Northern, the
   customer's accepted lead way must use ISO 17294-2:2016: the outsource dialog offers only subcontracted ways with the
   accepted method (`sample_test.py:296-303`), but the default lead way on Bottled water is AAS / TCVN 7602:2007
   (`parameter_method_sample_type.xml:34-42`). WF-01 Sales must switch the lead line to "Lead (Pb) – ISO 17294-2:2016"
   (in-house ICP-MS) when confirming ways; otherwise WF-05 needs a revised quotation.
6. **The renewal itself changes no state WF-05 can see.** Northern is already valid for 2 years in demo data, so the
   main A2 step only moves the date. To show "expired cannot be chosen, renewal restores it" by clicks, the journey must
   first set the date to yesterday (steps 9-12); this touches shared demo data for a few seconds and must happen before
   any journey dispatch exists. Coastal (the only expired demo subcontractor) must not be renewed (TC-F37-03).
7. **Head notification of draft dispatches (SF-06-A2) is cron-only.** It is queued by the daily job "Dispatches whose
   subcontractor's accreditation lapsed" (`subcontract_dispatch_scheduled_job.py:20-49`, `data/ir_cron_data.xml:83-89`)
   and fires only for draft dispatches. At step 2 no journey dispatch exists, so it is not walked. The administrator can
   trigger such jobs from Jobs → Scheduled Jobs → "Run now" (`button[name=action_run]`,
   `views/system/scheduled_job_views.xml:28`) if a later flow wants it.
8. **Dossier expiry warning (SF-06-A1) is cron-only too** (`quality_registration.expiry`, `ir_cron_data.xml:91-95`;
   admin.md:78). Not walked; renewal and coverage (steps 13-14) are clickable. Expiring the demo dossier would break
   TC-F42-01, so the journey only extends it.
9. **Report mark depends on the dossier's day, not on `valid_from`.** `_print_marks` filters only `valid_until`
   (`test_report.py:417-424`); harmless here, noted for completeness.
10. **Accreditation is recomputed by a daily job as well** (`accreditation.refresh`, `ir_cron_data.xml:75-80`), but
    adding the line recomputes matching applicabilities and open tests at once (`accreditation_scope_line.py:84-87`,
    `accreditation_certificate.py:89-102`), so no cron is needed in the journey.
11. **Re-runs add lines to the demo certificate.** Each run adds one VILAS 118 line for that run's parameter
    (parameters are `ondelete="restrict"` on lines, `accreditation_scope_line.py:44-51`), so the journey parameter can
    never be deleted later. Alternative if the owner prefers: create a new certificate `VILAS J{TAG}` (no dates, list →
    New, `code` field) and import into it.
