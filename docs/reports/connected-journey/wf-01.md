# WF-01 Order to confirmed test request: connected journey plan

## Position

Story step 4, between SF-09 part 1 (the new portal customer) and WF-02 (sample reception). SF-07 (step 5) runs inside this flow, at the cart and before the quotation is sent. The journey walks the WF-01 main path from a portal cart, with the advance paid through **WF-01-A4** (Sales records a bank transfer, the accountant confirms it), because PayOS cannot be reached. There is no Head of Sales approval in this journey: the threshold approval of the main path and WF-01-E3 is not built (finding 2). The other paths (WF-01-A1, A2, A3, A5, E1, E2, E3) are not walked; SF-02 walks WF-01-A3 later.

## Data

- `{TAG}` = `J<MMDD-HHmm>` of the run.
- Customer: `Journey Foods {TAG}` and its default contact, from SF-09.
- Lines (quantity 1 each, one sample):
  - `Journey nitrate {TAG}` on Bottled water, SF-08's in-house way, price and tax as SF-08 sets them (a tax with a rate valid today, e.g. `sol_demo.demo_tax_vat10`, 10 % since 2025-07-01).
  - Lead (Pb) `sol_demo.demo_test_parameter_lead` on Bottled water, way `sol_demo.demo_parameter_method_lead_icpms` (display `Lead (Pb) – ISO 17294-2:2016`, Chemistry, applicability `sol_demo.demo_parameter_method_sample_type_lead_icpms_bottled_water`). Price `sol_demo.demo_parameter_price_lead` = 250,000 VND, VAT10 in the demo data; Cypress specs expect 280.000, so read the price from the cart instead of typing it. Its subcontracted twin for WF-05: `sol_demo.demo_parameter_method_lead_subcontracted` (same method ISO 17294-2:2016, Northern Testing Laboratory `sol_demo.demo_subcontractor_northern_testing`, applicability `..._lead_subcontracted_bottled_water`). WF-05 offers a subcontracted way only with the method of the accepted way (`sol_laboratory/models/testing/sample_test.py:283-301`).
- Sample type: Bottled water `sol_demo.demo_sample_type_bottled_water` (Vietnamese name "Nước đóng chai" on vi screens). SF-08 must make the new parameter applicable to this sample type, or the two lines become two samples (`sol_commerce/models/orders/sale_order.py:598-613`).
- Expected sample pickup: tomorrow. Collection appointment (step 19): tomorrow 09:00.
- Quotation: Bank transfer, Percentage, 30, balance due Before the report, payment deadline as prefilled (now + the configured days, `quotation_send.py:163-178`), no discount.
- Advance = 30 % of the order total as the Payment tab shows it; balance = total − advance. Record payment: amount as prefilled, Bank transfer, received now, reference `Journey advance {TAG}`.
- Values read from screens and passed on: `ORDER`, `QUOTE`, `REQUEST`, the advance and balance amounts.

## Connection findings

1. **A portal order's test request is not paid at confirmation unless Sales changes the balance due.** A portal order gets `balance_due = before_collection` by default (`sol_commerce/models/orders/sale_order.py:226`); `_collection_hold` then holds the order until the balance is paid (`sale_order_confirmation.py:225-242`), so confirming leaves the test request `confirmed` (`sol_commerce/models/orders/test_request.py:35-41`), blocks Start sample collection, and refuses sample intake (`test_request.py:43-49`); it becomes `paid` only when the balance is funded (`payment_request.py:112-113`, `sale_order_confirmation.py:381-383`). Cypress shows the same: `orderAt("paid")` pays twice (`wf-01-order-to-test-request/setup.js:150-151`) and the main spec asserts collection stays hidden (`order-to-test-request.cy.js:106-111`). This contradicts business-flows.md:37 and sales.md:200 ("the balance holds back neither sample collection nor testing"). Journey: Sales picks Before the report in the Send quotation dialog (step 11, `quotation_send_views.xml:38`). Without it, WF-02 cannot start until SF-01 has run, which reverses the story.
2. **Head of Sales threshold approval is not built.** No threshold setting, approval state or button exists in `sol_commerce` (no match for threshold/approval in its models); the measuring rule is an open question (`questions/ecommerce.md:24,34`). Main-path approval and WF-01-E3 cannot be walked; the journey's amounts need no approval.
3. **WF-02 cannot find the test request by order number.** `order_number` is written only by the uninstall hook (`sale_order_confirmation.py:385-388`, `sol_commerce/hooks.py:30`), so the search field Order Number of test requests (`sol_laboratory/views/sample_collection/test_request_views.xml:177`) is empty while E-commerce is installed. Sample delivery staff search by customer `Journey Foods {TAG}` or by `REQUEST`, which only Sales sees on the order form.
4. **PayOS is replaced by WF-01-A4.** Cypress clicks PayOS and then switches to an RPC-built paid order (`order-to-test-request.cy.js:93-100`); its `payAdvance` posts the portal form and confirms the payment by RPC (`setup.js:96-112`). The journey records the transfer by Sales and confirms it in the accountant's Payments list, all by clicks. A click-only alternative is the customer's own report: the quotation page's Bank transfer button opens `#medilab_bank_transfer` with `received_at`, `reference` and "Report bank transfer" (`views/invoicing/portal_templates.xml:41-58`); it creates the same draft payment and task.
5. **Cypress RPC shortcuts that the journey replaces by screens:** the expected sample pickup is written by RPC (`order-to-test-request.cy.js:61-62`); the journey types it in the form (step 10). Carts are cleared by RPC (`setup.js:47-59`); the journey needs none because its customer is new. The accountant opens the payment by URL (`sf-01-payment-collection/payment-collection.cy.js:169`); the journey uses the Payments menu or the task queue.
6. **The default Lead way has no subcontracted twin.** Lead's default on Bottled water is AAS TCVN 7602:2007 (`sol_demo/data/sol_laboratory/parameter_method_sample_type.xml:34-43`); the only subcontracted Lead way uses ISO 17294-2:2016. If nobody changes the way (step 4 or 9), WF-05 finds no outsourcing way for the accepted method. Coliforms, E. coli and pH have no subcontracted way; Chlorpyrifos has one only on Cabbage.
7. **The customer cannot name the sample on the portal.** The order sample is created at sending, named after its sample type (`sale_order.py:607-609`), so WF-02 finds a sample called `Bottled water`, not a tagged name.
8. **E-mail.** Sending the quotation and the balance request queue e-mails and notices (`sale_order_confirmation.py:377-379`); no step waits for them. If the quotation PDF rendering fails, step 11 fails.
