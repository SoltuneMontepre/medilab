# SF-04 Sample retention, return and disposal: connected journey plan

## Position

Story step 16, after WF-06 (step 14) issued the report and SF-03 (step 15) issued its replacement. The journey walks
SF-04-A1: the journey's sample is not kept, so the demo tester disposes of it right after the report, by its disposal
method, and the sample records when, by whom and how. The main path (retention ends, daily to-do) cannot be walked:
no click makes days pass and the to-do comes from a daily cron. Two short variants are checked for clickability only:
SF-04-A2 (sample of the order cancelled in SF-02, step 18) and WF-06-A6 / SF-04-A3 (returns by sample delivery staff).

What decides "kept or not kept" and the retention days: only the sample type. `medilab.sample.type.is_retained`
("Retained After Testing") and `retention_days`
(`src/core/modules/sol_laboratory/models/master_data/sample_type.py:51-57`). Nothing on the order, the quotation,
the test request, the reception or the sample overrides it (tester.md "Retention policy"; `sample.retained_until` is
read-only, `models/sample_collection/sample.py:185`). At issue, `_issue` sets every completed sample to `reported`,
then `_retain` moves samples of a kept type to `retained` with `retained_until = report day + retention_days`
(`models/testing/test_report_issue.py:146-148`, `models/sample_collection/sample.py:502-510`). Only an upstream
change to the sample type, made in SF-08 (step 1) before WF-06 issues the report, can change the outcome.

## Connection findings

1. **A kept sample type makes SF-04-A1 unreachable and the main path cannot be walked by clicks.** If the journey uses
   Bottled water (the likely choice for a nitrate test plus subcontracted Lead), WF-06 leaves the sample `Retained`
   until report day + 30 (`test_report_issue.py:146-148`, `sample.py:502-510`). The Dispose button still shows for
   `retained` (`sample_views.xml:85`) but clicking it is refused: "Only a sample that is not kept, whose retention is
   over or whose test request was cancelled can be disposed of" (`sample.py:512-523, 580-590`). Nothing typed
   anywhere sets retention per order, request or sample. Consequence: SF-04 receives `Retained`, not `Reported`.
2. **The upstream choice that makes the step clickable belongs to SF-08 (step 1), before WF-06 issues the report**
   (`_retain` reads the type at issue). Options, in order of preference:
   A. Use Surface water as the journey's sample type (not kept): SF-04-A1 works with step 5 (the tester types the
      method; without it disposal is refused, `sample.py:524-527`). No demo record changes.
   B. Keep Bottled water and have the administrator set Retention Days to `0` in Master Data → Catalog → Sample Types
      (`sol_laboratory.menu_sample_type`, form fields `is_retained`, `retention_days`,
      `views/master_data/sample_type_views.xml:39-47`). The sample is then `Retained` with `retained_until` = report
      day, which `_retention_over` accepts the same day, so the tester disposes it with the type's method (main path
      disposal without the to-do), and SF-04-A3 becomes clickable. It changes a shared demo record; the journey must
      set it back to 30 at its end, and runs on the same database meanwhile see 0.
   C. Untick "Retained After Testing" on Bottled water: true SF-04-A1, same shared-record caveat as B.
3. **SF-02 order cancellation does not cancel the test request or its samples, so SF-04-A2 does not connect.**
   `sale.order._cancel_order` calls `_cancel_laboratory_documents` (`sol_commerce/models/orders/sale_order.py:423`),
   an empty hook ("once that model exists", `sale_order.py:432-433`) with no override anywhere in `src/`. The order
   ends cancelled while its test request stays `confirmed`/`paid` and its sample `expected`, which shows no Dispose
   button. `sol_commerce/tests/test_order_cancellation.py` asserts only the order status. This contradicts SF-02's main
   path ("the order and its test request are cancelled"). Workaround by clicks: sample delivery staff or Sales cancel
   the test request itself (variant A2-1), which cancels its samples (`test_request.py:242-245`, `sample.py:313-318`).
   Cypress `setup.js` `cancelledSample()` likewise cancels the test request by RPC, never through the order.
4. **No to-do or notification for a not-kept or cancelled sample.** The daily to-do (`sample_retention` task in the
   department queue, Tasks → Department queue `/odoo/awaiting-tasks` → Claim, then My tasks `/odoo/my-tasks` → row
   opens the sample) is created only for `retained` samples whose `retained_until` is within the reminder days
   (`models/sample_collection/scheduled_job.py:26-48`), by cron `sol_laboratory.ir_cron_sample_retention_reminders`
   (daily). SF-04-A1 "right after its report" has no trigger on screen: the tester finds the sample in the Samples
   list. Even with option 2B the to-do needs the cron; Cypress fires it by RPC (`setup.js` `remindRetention`). A
   click-only alternative is the administrator in developer mode: Settings → Technical → Scheduled Actions → "Sample
   retention reminders" → Run Manually (to verify that it queues and handles the item in one run).
5. **Cypress builds the reported sample by RPC.** `setup.js` `reportedSample()` writes `status`/`retained_until` as the
   administrator, skipping WF-06; the journey replaces that with the sample WF-06 issued.
6. **WF-06-A6 must happen before disposal.** `_compute_returnable` gives nothing for a `disposed` sample
   (`sample_returns.py:51-53`); the A6 return needs a signed WF-02 handover record line with `extra_count` or
   `excess_material` (`sample_returns.py:57-65`). If WF-02 records no excess, the Return button never shows.
7. Retained samples after SF-03: the replacement issue moves only `completed` samples (`test_report_issue.py:146`), so
   a sample disposed between WF-06 and SF-03 would not block SF-03, but the journey keeps SF-04 after SF-03 anyway.
